# T4 — Type-Contract Hunt Brief (Night-Shift Wave 1, READ-ONLY)

Scope audited: `core/conversation.py`, `core/events.py`, `interface/{repl,tui,renderers,intent_parser}.py`, `messaging/envelope.py`, `assistant/briefing.py`, `calendar/{auth,events,graph_sync}.py`, `utils/{aja_guard,redact,nl_time,tokenizer_map,local_extractor}.py`. Consumers traced into `gateway/orchestrator.py`, `gateway/remote_control.py`, `scheduler/{telegram,cron_scheduler}.py`, `tui/dashboard.py`, `orchestration/{gateway,direct_loop}.py`.

## Findings

### F1 — `tui.py:251-255` — HIGH — async gateway method run through `run_in_executor` → membership test on a coroutine
```python
response = await loop.run_in_executor(None, self.gateway.chat, self.model, prompt)
...
if "```" in response:   # line 255 (via "<cmd>" in response)
```
`LLMGateway.chat` is `async def chat(...)` (orchestration/gateway.py:293). Calling it inside a thread pool worker returns an **un-awaited coroutine object** (RuntimeWarning: never awaited), so `response` is a coroutine and `"<cmd>" in response` raises `TypeError: argument of type 'coroutine' is not iterable`.
- **Data-origin trace**: `AJAShell.on_input_submitted` (interface/tui.py:213) → natural-language branch → `self.gateway = LLMGateway(provider, key)` (line 142) → `chat()` defined async at orchestration/gateway.py:293. Even if it were sync, the legacy path returns `None` on failure (gateway.py:624/627) → `"```" in None` TypeError; adapter path with tools returns a dict (gateway.py:327).
- **Proposed guard**: `resp = await self.gateway.chat(self.model, prompt)` on the event loop (it's already async), then `if not isinstance(resp, str): resp = ""` before any substring tests.

### F2 — `intent_parser.py:448-449 / 528-529` — MEDIUM-HIGH — raw LLM JSON returned unvalidated; consumers call `.get` on possibly non-dict
```python
data = json.loads(raw)
return data            # no isinstance(data, dict), no schema check
```
If the model returns a top-level JSON array/scalar/string, every downstream consumer crashes:
- `gateway/remote_control.py:30` — `intent.get("response")` → `AttributeError: 'list' object has no attribute 'get'`.
- `scheduler/telegram.py:50-51` — same `.get` pattern.
- `scheduler/cron_scheduler.py:189` docstring wiring prescribes `intent["task"]` → future integrators get `KeyError` when the LLM omits `task` (the prompt only *asks* for the field; nothing enforces it).
Also `scheduler/telegram.py:65` — `intent_data.get("command").lower()` raises if the LLM emits a non-str `command` (truthy dict/list passes the guard).
- **Data-origin trace**: `parse_intent`/`parse_intent_async` are fed Telegram text via `remote_control.execute_local_control:29` and `telegram.handle_telegram_message:48`; the JSON comes from an arbitrary LLM completion after fence-stripping — shape is unguaranteed (repo already has `aja/llm_structured.py` for exactly this).
- **Proposed guard**: after `json.loads`, require `isinstance(data, dict) else fall back to the existing question-fallback`; coerce `type/response/confidence` to str/str/float defaults; reuse `llm_structured` validator or a tiny `_normalize_intent()`.

### F3 — `core/conversation.py:497→500` + consumers — MEDIUM — `history content=None` flows into `Delta(text=None)` → renderer crash
```python
final_text = m.get("content", "")   # returns None when key EXISTS with value None
...
if final_text:
    yield Delta(text=final_text)     # wait: guard catches falsy... but see below
```
The `if final_text:` at line 499 happens to block `None` **here**, but two adjacent paths do not:
1. Line 215: `final_text = ev.text` from a `Final` event — all current Final producers pass literals, but `Final(text=...)` is a plain dataclass (`events.py:65-69`) with no validation; any handler regression reintroduces `None`.
2. The same `m.get("content", "")` idiom is used in `direct_loop.py:235` transcript join (f-string tolerates None) and `orchestrator.py:898` (`h.get('text', '')`) — safe there, but session stores loaded from LanceDB-backed `SessionStore` implementations may hold `{"role": "assistant", "content": None}`, which then reaches `session["history"].append` copies.
Downstream blast radius if `Delta.text`/`Final.text` is ever None:
- `renderers.py:49` — `escape(None)` → TypeError inside `re.sub`.
- `renderers.py:147` — `render_delta(event.text)` no guard.
- `tui/dashboard.py:537` — `_delta_buffer.append(None)` → `"".join` TypeError in `_tick_spinner` (dashboard.py:589).
Note `repl.render_final` (repl.py:725) was just hardened with `(ev.text or "")`; **none of the other Delta/Final consumers got the same treatment** (`renderers.stream_events:147/161`, `dashboard.render_event:537/556` guards text-only at Final, not Delta).
- **Proposed guard**: normalize at the source — `final_text = m.get("content") or ""` in conversation.py:497, and defensive `text = ev.text or ""` in renderers.py stream driver + dashboard Delta branch.

### F4 — `messaging/envelope.py:73-81` — MEDIUM (latent, contract-level) — dataclass type hints are NOT runtime validation
`InboundMessage.text: str = ""`, `chat_id: str`, `user_id: str` look guaranteed but are plain dataclasses: any caller passing `text=None` explicitly (e.g. a future adapter doing `InboundMessage(surface=..., chat_id=..., user_id=..., text=message.content)` where `message.content is None`) silently injects None past the default. Today's adapters sanitize (`discord_envelope.py:44 content = message.content or ""`, `telegram_envelope.py:266 ... or ""`), so this is a **contract trap**, not a live crash — exactly the class that produced the recently fixed `model=None → .startswith` bug. `ConversationCore.handle` (conversation.py:197) already does `(msg.text or "")`, but `_stage_intake` uses `msg.chat_id` / `msg.user_id` raw (lines 237/242) → a None chat_id would create a `"None"`-keyed session or crash `sessions.load`.
- **Proposed guard**: `__post_init__` coercion (`self.text = self.text or ""`, `str(self.chat_id)`) or migrate envelope to pydantic v2 (see Internet research).

### F5 — `utils/tokenizer_map.py:72-79` — LOW — non-str payloads silently miscounted through the Rust fast path
```python
if not text: return 0
if family == "cl100k":
    exact = _native_count(text)   # try/except swallows Rust TypeError on non-str
```
A non-empty list/dict payload (multimodal block passed directly instead of via `estimate_messages_tokens`) hits `aja_native.count_tokens(list)` → exception swallowed by the bare `except Exception` (tokenizer_map.py:59) → falls to `len(text)/chars_per_tok` = e.g. 3 blocks ÷ 3.9 ≈ 1 token. Context-window decisions then over-trust a nearly-empty budget. No crash, but a silent wrong-answer path adjacent to the multimodal-list crash class.
- **Proposed guard**: `if not isinstance(text, str): return estimate_messages_tokens(...)` or log-and-fallback on non-str.

## Internet research
- **Dataclasses perform zero runtime type enforcement** — annotations are ignored by `@dataclass` ("nothing in @dataclass examines the type specified in the variable annotation"); None can be assigned/passed regardless of declared `str` type; pydantic-style validation requires a third-party library or manual `__post_init__` checks.
  - https://docs.python.org/3/library/dataclasses.html
  - https://stackoverflow.com/questions/53033155/how-to-assert-types-in-python3-dataclasses ("Dataclasses are not intended to provide runtime type-checked fields")
  - https://github.com/python/mypy/issues/13934 (confirms "It does not enforce any runtime typing" — enforcement belongs to static checkers or pydantic/attrs)
- **Google Calendar all-day events return `date` only; `dateTime` is absent** — EventDateTime schema: `start.date` = "The date, in the format yyyy-mm-dd, if this is an all-day event"; concept guide: "All-day events use the start.date and end.date fields… timezone field has no significance". AJA's `dateTime or date` fallback in `calendar/events.py:23-24` is therefore correct; briefing display shows midnight-UTC "at HH:MM" for all-day events (cosmetic, not a crash).
  - https://developers.google.com/workspace/calendar/api/v3/reference/events (EventDateTime / start.date vs start.dateTime)
  - https://developers.google.com/workspace/calendar/api/concepts/events-calendars ("Events may also be timed or all-day")

## Proposed claims
1. F1 is a certain crash on any natural-language input in the Textual shell (`interface/tui.py`); fix is mechanical (await the coroutine + str-coerce). Possibly the whole `AJAShell` legacy surface should be deleted rather than fixed — it duplicates ConversationCore paths.
2. F2 warrants a single `_normalize_intent()` shared by both parse functions; the repo already owns `llm_structured.py` and Phase-10 added a planning recovery ladder — intent parsing is the last unvalidated LLM-JSON boundary in the chat path.
3. F3: apply the `(ev.text or "")` hardening that landed in `repl.render_final` uniformly to `renderers.stream_events` and `dashboard.render_event`'s Delta branch — one-line each.
4. F4: prefer a stdlib `__post_init__` coercion over a pydantic migration to preserve the documented import-time purity contract of `envelope.py`/`events.py`.
