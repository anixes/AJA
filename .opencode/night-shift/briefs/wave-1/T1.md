# T1 Brief — Type-Contract Bug Hunt, `libs/aja-core/aja/gateway/`

Agent: T1 (Type-Contract subgroup) · Wave 1 · READ-ONLY research
Scope: all files under `libs/aja-core/aja/gateway/` (+ data-origin traces into memory/runtime/persistence layers)
Reference live bugs of this class: (a) `model=None` -> `.startswith` in orchestration/gateway.py (fixed); (b) multimodal list `content` -> `.lower()` in gateway/orchestrator.py (fixed).

## Findings

### F1 - CRITICAL - NULL `status` rows crash both telemetry pollers and are silently dropped
- Files: `gateway/tg_client.py:455`, `gateway/adapters/discord_adapter.py:640`
- Code: `status = ev.get("status", "success").upper()`
- Data-origin trace (confirmed at runtime):
  - `aja_runtime_events` is created by `memory/secretary.py:259-260` with schema `(event_id, kind, target, status, message, command, metadata_json, timestamp)` (`secretary.py:176-187`).
  - A SECOND writer, `persistence/tracker.py:log_event()` (lines 8-25), adds rows to the SAME table with a different shape: `{event_id, event_type, message, level, created_at}` - no `kind`, no `status`, no `metadata_json`, no `timestamp`. LanceDB fills absent columns with NULL.
  - `tracker.log_event` is actively called by `presence/agent_loop.py` (~15 sites: AGENT_LOOP_TICK, CIRCUIT_BREAKER_TRIGGERED, ...), `planning/execution_bridge.py:53`, `planning/replanner.py:266`, `decision/context.py:85`, `skills/skill_executor.py:557`, `skills/skill_postconditions.py:244`, `skills/skill_composer.py:317`, `presence/approval.py`.
  - Any agent-loop tick while a gateway runs inserts a NULL-status row. On the next 1s poll, `ev.get("status", "success")` returns None (the key EXISTS in the Arrow schema - `.get` default only applies to missing keys; Arrow rows materialize every column) and `.upper()` raises AttributeError.
  - Aggravator: pollers add `eid` to `seen_event_ids` BEFORE processing (`tg_client.py:447`, `discord_adapter.py:634`) and swallow the exception in the outer `except` (`tg_client.py:485`, `discord_adapter.py:674`). Net effect: the row is permanently dropped without delivery and the rest of that batch iteration is skipped.
- Proposed guard: `status = str(ev.get("status") or "info").upper()`; move `seen_event_ids.add(eid)` after successful enqueue; unify tracker.log_event onto RUNTIME_EVENTS_SCHEMA.

### F2 - HIGH - SlackAdapter lacks `start_tail`/`tail_events`: MISSION intent on Slack crashes, user gets no reply
- File: `gateway/orchestrator.py:614-620` (via `gateway/gateway_runner.py:93-99`)
- Trace:
  - `GatewayRunner.process_event` swaps `orchestrator.telegram_adapter` for an AdapterProxy around ANY adapter event (discord/slack included), then calls `handle_gateway_event`.
  - On MISSION intent: `if hasattr(self.telegram_adapter, "start_tail"): ... else: asyncio.create_task(self.telegram_adapter.tail_events(chat_id))`.
  - `adapters/slack_adapter.py` defines NEITHER method -> else branch evaluates `self.telegram_adapter.tail_events(...)` -> AttributeError escapes `handle_gateway_event`; caught only by runner log-and-continue (`gateway_runner.py:69-70`). Mission already created (line 599) but the confirmation reply (line 694) never sends.
- Class: return-type/contract drift across adapter surface (checklist #5).
- Proposed guard: no-op `start_tail`/`tail_events`/`stop_tails` on SlackAdapter (and AdapterProxy fallback), or feature-detect both methods before bridging.

### F3 - HIGH - `create_mission()` returns Optional; caller indexes unconditionally
- File: `gateway/orchestrator.py:599-607`
- Trace:
  - `AJAMemory.create_mission` (`memory/secretary.py:439-448`) emits then returns `self.get_mission(mid)`.
  - `get_mission` reads the LanceDB `aja_missions` projection that exists only via MissionJournal emit write-through - which is best-effort, failures logged+swallowed (`runtime/mission_journal.py:158-165`). Under transient LanceDB lock contention (realistic on VPS where `aja serve` + workers share DATA_DIR), create_mission returns None.
  - Caller does `mission["mission_id"]` twice -> TypeError -> whole turn aborts with zero user feedback.
  - Contrast: `approvals.py:60-64` handles mission-is-None correctly - inconsistent contract handling.
- Proposed guard: `if not mission: reply failure + return`.

### F4 - MEDIUM - Slack NULL-text messages become a phantom vision prompt
- Files: `adapters/slack_adapter.py:90` -> `gateway/orchestrator.py:452`
- Trace:
  - Slack builds `text=event.get("text")` - genuinely None-able: attachment-only / `file_share` subtype messages may omit or null `text` (docs.slack.dev/reference/events/message).
  - Orchestrator line 452: `content = event.text or "What can you see in this image?"` coerces None into the VISION DEFAULT PROMPT, which is then intent-routed as if the user asked about an image (none attached).
  - Silent wrong-behavior bug, not a crash. PTB path immune (tg_client.py:203 coalesces text/caption to ""); Discord immune (`or ""` + empty-drop at discord_adapter.py:216/238).
- Proposed guard: slack adapter `event.get("text") or ""` + same no-text-no-media reject rule; or orchestrator applies vision-default only when `event.media_urls` non-empty.

### F5 - MEDIUM - `GatewayState.get_session` can return non-dict JSON, wedging a chat permanently
- File: `gateway/persistence.py:55-61` -> consumers `orchestrator.py:455, 482, 541, 689, 708-713`
- Trace: catches only `(TypeError, ValueError)` from loads. If `session_json` holds valid-but-non-object JSON (`null`, string, list - anomalous/cross-version write), loads succeeds and returns it unvalidated; callers immediately do `session.pop(...)` / `session["history"].append(...)` -> AttributeError/TypeError for EVERY subsequent message in that chat until manual repair.
- Plausibility medium-low (needs anomalous write), severity high when hit.
- Proposed guard: `if not isinstance(parsed, dict): return {"history": [], "metadata": {}}`.

### F6 - LOW - `"AJA Warning" in content` where history `content` can be explicitly None
- File: `gateway/orchestrator.py:114-115`
- Trace: `content = h.get("content", h.get("text", ""))`. `.get` default does not fire when the key exists with value None - OpenAI chat messages legally carry `content: null` (assistant tool-call turns); any caller feeding raw OpenAI-style history crashes with `TypeError: argument of type 'NoneType' is not iterable`. List-valued content does NOT crash (`in` = membership) but silently defeats the warning-filter. Current internal callers (session["history"]) always store str, so latent.
- Proposed guard: `content = h.get("content") or h.get("text") or ""`.

### F7 - LOW - STATUS sort key mixes None with str
- File: `gateway/orchestrator.py:676`
- Trace: `sorted(..., key=lambda m: m.get("updated_at", ""))`. Arrow `updated_at` is nullable utf8; `.get` default does not fire for explicit NULL values. Mixed None/str rows -> TypeError inside the STATUS branch -> turn aborts. Current writers (`runtime/mission_journal.py:242-252`) always set strings; latent until another writer appears.
- Proposed guard: `(m.get("updated_at") or "")`.

### F8 - LOW - `interaction.data` may be None in Discord interaction handler
- File: `gateway/adapters/discord_adapter.py:310-312`
- Trace: `getattr(interaction, "data", {}).get("custom_id", ...)`. The getattr default does NOT help when the attribute exists with value None - discord.py types `Interaction.data` as Optional[dict]; for interaction kinds that carry no data payload this is None -> AttributeError on `.get`. Escapes into discord.py's event error handler (logged upstream, no crash of the bot). Low frequency.
- Proposed guard: `(getattr(interaction, "data", None) or {}).get(...)`.

## Internet research

1. OpenAI message content is a real str | list-of-parts | null union (input side), confirming bug-class (b) and F6:
   - https://community.openai.com/t/difference-in-content-format/1082242
   - https://github.com/openai/openai-node/issues/462 ("content: string | Array<ChatCompletionContentPart> | null")
   - https://community.openai.com/t/results-syntax-different-than-input-syntax/988923/1
   - https://javadoc.io/static/com.openai/openai-java/4.6.1/com/openai/models/chat/completions/ChatCompletionUserMessageParam.Content.html
2. python-telegram-bot v20: `Message.text` and `Message.caption` are Optional[str] (None-able); `chat_id` is int (adapters correctly str()-wrap it):
   - https://docs.python-telegram-bot.org/en/v20.0/telegram.message.html ("text (str, optional)", "caption (str, optional)", chat_id -> int)
   - https://github.com/python-telegram-bot/python-telegram-bot/blob/v20.0/telegram/_message.py (from_user Optional - channel posts; matches tg_client.py:183 guard)
3. Slack Events API message events: `text` not guaranteed present across subtypes (file_share etc.), so F4's None-text path is real:
   - https://docs.slack.dev/reference/events/message
   - https://docs.slack.dev/reference/events/message/file_share

## Proposed claims

1. C1: Every gateway telemetry poller row-processing step must be None-tolerant per column; `.get(key, default)` is NOT a None guard for Arrow-backed rows because columns always exist. (F1)
2. C2: Adapter feature-detection must cover the full method set actually invoked downstream (`start_tail` AND `tail_events`), or adapters should share a base contract declaring them. (F2)
3. C3: Any gateway call chain crossing into AJAMemory must treat mission/task getters as Optional and degrade with a user-visible message. (F3)
4. C4: `or <sentinel-string>` coercion of `event.text` is only safe when the sentinel is contextually valid (media attached); prefer normalizing at the adapter boundary. (F4)
5. C5: Persisted JSON blobs loaded from storage need post-load type validation, not just parse-error handling. (F5)

## Council questions

1. F1: should the fix be defensive at the poller (str-coalesce) or structural (single writer schema for aja_runtime_events)? tracker.log_event callers span presence/planning/skills - who owns that migration?
2. F2: is SlackAdapter considered production-supported? If yes, is the right fix parity (tails over SocketMode events) or explicit unsupported-intent rejection?
3. F3: should `MissionJournal.emit` write-through failure be retried/surfaced instead of swallowed, given gateway callers now depend on projection reads for control flow?
4. Do we want a repo-wide convention replacing `x.get(k, default)` with `x.get(k) or default` wherever the store is Arrow/LanceDB-backed? A lint rule could catch the pattern class.
5. F6/F7 are latent today (internal writers always set strings). Fix now cheaply, or gate behind the same audit sweep as P4 bare-except triage?
