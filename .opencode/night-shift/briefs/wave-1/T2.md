# T2 — Type-Contract Bug Hunt Brief (Wave 1)

Scope: `libs/aja-core/aja/orchestration/**` (incl. `tools/`, `providers/`), `aja/llm.py`, `aja/llm_structured.py`.
Reference class (already fixed live): `model=None` → `.startswith` crash; multimodal list content → `.lower()` crash.

---

## Findings

### F1. `resolve_provider_model(None)` — `"in None"` TypeError on null config key
- **File:line**: `libs/aja-core/aja/llm.py:54` (also reached from `llm.py:34`, `503`, `557`, `574`)
- **Severity**: HIGH (crash, exact same class as the already-fixed `model=None` bug)
- **Description**: `":" in model_str` at llm.py:54 and `model_str.lower()` at llm.py:60-66 assume a non-None string.
- **Data-origin trace**: All four raw JSON readers use `cfg.get("swarm_settings", {}).get("models", {}).get("planner", "<default>")`. Python's `.get(key, default)` returns **None, not the default**, when the key exists with JSON value `null`. So an `aja.json` containing `"swarm_settings": {"models": {"planner": null}}` (a natural way users "unset" a model) yields `model=None`. Note `aja/config.py::_get_default_model` (line 121-127) *does* guard this (`return val if val else default`) — but `llm.py` bypasses pydantic entirely with raw `json.load`, so the guard doesn't apply. The crash propagates out of `get_gateway()` (llm.py:37 is outside its try) and out of `completion()`/`completion_async()`/`completion_stream()` (the try blocks only wrap file reads).
- **Proposed guard**: `model_str = model_str or ""` (or `if not model_str: return ("openrouter", "")` semantics) at the top of `resolve_provider_model`; alternatively normalize all four read sites with `or DEFAULT`.

### F2. Gemini empty-candidates IndexError on safety-blocked prompts (2 sites)
- **File:line**: `libs/aja-core/aja/orchestration/gateway.py:784` (`data.get("candidates", [{}])[0]`), `libs/aja-core/aja/orchestration/providers/google_adapter.py:115` (identical expression)
- **Severity**: HIGH (uncaught IndexError inside adapter path; gateway legacy path catches it only as generic retryable exception)
- **Description**: The default `[{}]` only applies when the `candidates` key is **absent**. When Google blocks a prompt (`promptFeedback.blockReason` set), the response contains `"candidates": []` — an *empty list* — so `[0]` raises `IndexError: list index out of range`.
- **Data-origin trace**: Per Google's own API reference, prompt-blocked responses carry no candidates ("only happens when no candidates were generated due to content violations") — see https://cloud.google.com/vertex-ai/generative-ai/docs/reference/rest/v1/GenerateContentResponse and https://ai.google.dev/gemini-api/docs/safety-settings. AJA sends arbitrary user objectives + tool outputs into Gemini; safety triggers are routine in autonomous missions.
- **Proposed guard**:
  ```python
  candidates = data.get("candidates") or []
  parts = (candidates[0].get("content", {}).get("parts", [])) if candidates else []
  ```
  Return an empty `LLMResponse`/`None` (optionally logging `promptFeedback.blockReason`).

### F3. `response.choices[0]` without empty-choices guard (Copilot/local-model reality)
- **File:line**: `libs/aja-core/aja/orchestration/gateway.py:599` (`response.choices[0].message`), `libs/aja-core/aja/orchestration/providers/openai_compat.py:207` (same)
- **Severity**: MEDIUM-HIGH
- **Description**: Both assume `choices` is non-empty. Three independently documented real-world producers violate this:
  1. GitHub Copilot's newer Claude backends (`claude-opus-4.7/4.8`) return OpenAI-format responses with `choices: []` (Anthropic-native passthrough) — LiteLLM had to synthesize choices twice ([PR #29392](https://github.com/BerriAI/litellm/pull/29392), [PR #30929](https://github.com/BerriAI/litellm/pull/30929)). AJA routes Claude models through Copilot (`gateway.py:363` forces Responses for claude, but non-claude copilot models go through chat completions).
  2. llama.cpp/vLLM/Ollama-compatible servers emit a spec-compliant final chunk / response with `"choices": []` when usage stats are requested (VS Code issue #324335 root cause analysis).
  3. Content-filter finishes can yield empty choices on proxies.
- **Data-origin trace**: AJA explicitly supports llama_cpp/ollama local endpoints (gateway PROVIDERS table) where these payloads are common; the Copilot provider is AJA's primary cloud path.
- **Proposed guard**: `if not getattr(response, "choices", None): return LLMResponse(content="", model=model)` / `return None` before indexing. (Stream paths already do this correctly via `chunk.choices and ...`.)

### F4. `SwarmEngine(model=None)` → `":" in None` TypeError; empty-string env silently misroutes
- **File:line**: `libs/aja-core/aja/orchestration/swarm.py:52` (crash) and `swarm.py:50` (empty-string path)
- **Severity**: MEDIUM
- **Description**: `model_resolved = model if model != "llama-3" else (...)`; if callers pass `model=None`, line 52 raises `TypeError: argument of type 'NoneType' is not iterable`. Separately, `AJA_PLANNER_MODEL=""` (env var set to empty string — `os.getenv` returns `""`, NOT the default, per config.py:130) flows through `GoalSwarmSession` (goal_session.py:146) → swarm resolves provider via `"gemini" in "".lower()` → falls through to `AI_PROVIDER`/google while `self.model=""`, then `get_gateway_for_model("")` → `resolve_provider_model("")` returns default provider `openrouter` with `model_name=""` — a silent misroute to OpenRouter with an invalid empty model id.
- **Data-origin trace**: programmatic construction (`SwarmEngine(provider, key, model)` public signature); empty env vars are a classic deployment mistake (docker-compose writes `VAR=` easily). `goal_session.py:146-147` passes `AJA_PLANNER_MODEL`/`AJA_CRITIC_MODEL` straight through.
- **Proposed guard**: `if not model_resolved: model_resolved = AJA_PLANNER_MODEL or "google:gemini-2.0-flash"` after line 50; treat falsy as unset everywhere.

### F5. plan_gate: `None` chat responses hit `.get()` (silent quality degradation)
- **File:line**: `libs/aja-core/aja/orchestration/plan_gate.py:40` (`response.get("content","")` when response is None) and `plan_gate.py:75` (`plan_resp.get(...)` when None)
- **Severity**: LOW-MEDIUM
- **Description**: `LLMGateway.chat` legitimately returns `None` on exhausted retries or non-retryable 4xx (gateway.py:624, 627). `isinstance(None, str)` is False → branch calls `None.get(...)` → AttributeError. In plan_gate both sites are swallowed by broad `except Exception` handlers, so the user-visible effect is the complexity check being silently skipped / "Failed to generate plan" — but it masks the real cause (provider outage vs parse issue) and defeats the intended `needs_plan=True` safe-default logic.
- **Data-origin trace**: any provider failure (bad key, quota, network) makes `chat()` return None deterministically.
- **Proposed guard**: `if not response: needs_plan = True; return goal_request` (and analogous early-out for the plan call).

### F6. Google message conversion embeds non-str content into `{"text": <value>}` payload (2 sites)
- **File:line**: `libs/aja-core/aja/orchestration/gateway.py:731` + `:735` (`text = m.get("content", m.get("text", ""))` → `{"parts": [{"text": text}]}`), `libs/aja-core/aja/orchestration/providers/google_adapter.py:93-94` (same)
- **Severity**: MEDIUM
- **Description**: This is the *sibling* of the fixed multimodal `.lower()` crash: instead of crashing locally, a list-typed `content` (OpenAI vision format: `[{"type":"text",...},{"type":"image_url",...}]`) is serialized verbatim as the Gemini part text, producing an API 400 that then burns through all retries and surfaces as `None`. Additionally every non-user role (including `tool` results and `assistant` turns carrying `tool_calls`) is collapsed to role `"model"` with plain text — tool-call history sent to Gemini is structurally wrong (function responses must be sent as `functionResponse` parts), which degrades tool-loop reliability rather than crashing.
- **Data-origin trace**: DirectSession history persists assistant/tool messages verbatim (direct_loop.py:175,223); any google-provider mission with tool history hits this path.
- **Proposed guard**: flatten list contents to concatenated text parts (mirroring the anthropic adapter's block handling at anthropic_adapter.py:91-100); map `role=="tool"` messages to `functionResponse` parts or at minimum prefix-tag them.

### F7. Unvalidated env-var numeric contracts
- **File:line**: `libs/aja-core/aja/orchestration/swarm.py:441` (`int(os.getenv("AJA_WORKER_TIMEOUT_S", "600"))`), `libs/aja-core/aja/orchestration/context_window.py:33-35` (`int(os.environ.get("AJA_MAX_TOOL_RESULT_CHARS", "8000"))`)
- **Severity**: LOW
- **Description**: A garbage/empty env value (`AJA_WORKER_TIMEOUT_S=` written by tooling) raises uncaught ValueError mid-dispatch (swarm) or at import time (context_window — module-level evaluation crashes every import of the module).
- **Data-origin trace**: docker-compose/.env templates encourage setting these knobs (VPS profile documents timeout knobs per AGENTS.md Phase 12).
- **Proposed guard**: small `_env_int(name, default)` helper with try/except + warning.

### Verified NON-findings (checked, safe — recorded to prevent re-flagging)
- Tool-argument str/dict duality: producers all emit strings (openai_compat.py:215 `tc.function.arguments`; anthropic_adapter.py:157 & google_adapter.py:127 `json.dumps(...)`; base.py:22 declares `arguments: str`). Consumers `direct_loop.py:186-190` and `llm_structured._extract_and_validate` (llm_structured.py:164-181) both handle str AND dict. Contract holds end-to-end.
- `chat_stream` copilot `model.startswith("copilot:")` (gateway.py:656): guarded by preceding `not model` branch (652-655). Safe.
- `normalize_google_model` / `_is_claude_model`: `(model or ...)` guards present. Safe.
- `activity_rt.py:290 result_str.startswith(...)`: every NativeToolRegistry tool returns `str` (verified all defs native.py:731-1154). Safe.
- `Activity.timeout_s` has dataclass default 120 (activity_rt.py:35). Safe.
- `context_window.resolve_model_limit(None,...)`: `(model or provider or "")` guard. Safe.

## Proposed claims

- C1 (F1): "Raw `json.load` config reads in `llm.py` defeat the pydantic-layer null-guard; a single `or DEFAULT` normalization at `resolve_provider_model` entry closes four crash sites."
- C2 (F2): "The identical `data.get('candidates', [{}])[0]` expression exists in two files and both are IndexErrors-on-safety-block; fix once in a shared parser."
- C3 (F3): "Empty-choices tolerance should be added at BOTH the gateway legacy path and openai_compat adapter; upstream evidence (LiteLLM, VS Code, vLLM) shows this is not theoretical."
- C4 (F5): "`plan_gate`'s broad excepts convert provider outages into silent skips — a falsiness check restores the documented safe-default."
- C5 (F6): "Google adapters need a content-flattening layer mirroring anthropic_adapter's system-block handling, plus correct tool-role mapping."
- Test-seam suggestion: each guard is unit-testable with frozen fake payloads (`{"candidates": []}`, `choices=[]` stub object, `"planner": null` aja.json fixture).

## Council questions

1. F1: should the fix normalize at `resolve_provider_model` entry, or ban raw `json.load` config reads in favor of `CONFIG` (pydantic) everywhere — the latter is broader but prevents recurrence?
2. F2/F3: on empty candidates/choices, is returning `None` (current retry-exhaustion contract) preferable to raising a typed `ProviderBlockedError`? Callers like `direct_loop` already handle falsy.
3. F6: full `functionResponse` mapping for Gemini tool history is a feature, not a patch — do we scope-creep or ship text-flattening now?
4. F4: is `SwarmEngine(model=None)` a supported public API (needs a guard + test) or should callers be fixed and a type annotation added instead?
